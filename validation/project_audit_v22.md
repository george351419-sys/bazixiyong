## 当前流程

生辰输入校验 → 公历/农历转换及显式时间校正 → 真实历法排盘 → 合化与旺衰 → 外格前置/普通格局 → 独立调候 → 同一事实基线下的需求与候选路线 → 审核证据 → 条件、药效、承受、剂量和资源核查 → 最终裁决与范围发布。

普通直接调用analyze(chart)默认保留rule_case兼容模式，便于既有规则测试；返回input_validation说明历法一致性。网页与CLI的直接四柱入口默认real_chart，只有显式勾选构造案例/传--rule-case才允许违反历法推导。analyze_birth始终使用真实命盘合同。

输入时间沿用项目的北京时间口径，不暗推海外时区。真太阳时、均时差、夏令时和sect均记录约定。缺失时辰及不明确的“子时”返回需要补充信息，不拿中午占位生成结论。

## 结构需求补充合同

prepare_fusion_context返回unresolved_geju_targets，键为既有账行的规范需求ID。审核评估器可在fusion_evidence.needs提交need_type=geju的补充需求，必须：

1. 目标ID及source_target_id、source_demand_method、source_scenario_id、source_bundle_id与原始账一致。
2. source_ledger_row为完整原始账行，且原始initial_demand确实未量化；不得替换已测数值或掩盖数值矛盾。
3. baseline_ref、facts_snapshot_id、assessment_snapshot_id及evidence_registry逐项绑定；need证据包含来源账。
4. coverage.geju列出全部格局需求；路线仍须覆盖所有必需目标，并通过药效、资源、兼容与政策核查。

该通道补的是审核评估，不表示程序已经会自动给所有定性结构病换算数值。测试中的合成药效只验证通道可用。

## v23 补充：本轮新增问题与处理

| 发现 | 修复 | 阻断效果 |
|---|---|---|
| 计划路线的条件表达式只在延期态检查 | 对计划目标及动作条件都做结构校验和三态求值；假条件拒绝路线，未知或非法条件阻断，条件必须在目标与动作间一致 | 正向药效不能绕过执行前提 |
| 承受安全只在部分政策命中时检查 | 所有带 increase 意图的路线均需绑定 bearing_safe=true 的核验记录 | 明确不安全拒绝，缺证据待判 |
| 任意 choice_group 可隐藏扶抑/通关等独立正需求 | 限定互斥组为同一类型、场景、目标、来源包下的不同需求方法 | 独立维度需求不能被“二选一”标签漏掉 |
| 真太阳时经度修正后与北京时间节气历表混用 | 年、月柱使用经夏令时归一后的标准北京时间；真太阳时用于日、时柱；节气天数按同一标准时间基准计算 | 经度变化不再单独推动年、月柱跨节气 |
| 中文日期中的“公历/阳历”未获最高优先级 | 显式历法标记优先；与参数或互相冲突时返回错误 | “公历1990年五月十五”不再误判成农历 |
| 下午时段只在部分格式生效 | 统一时段修饰应用到时:分、点半、阿拉伯数字和中文数字；矛盾小时数拒绝 | 不同输入写法得到同一24小时结果 |
| 秒被截断导致节气边界柱错 | 秒进入文本、数字、CLI、网页及历法库转换；节气临界秒级反例验证 | 不再静默丢失秒精度 |
| 汇总验收可在零发布样本、无独立领域审定时通过 | 明确要求至少一个方向与行动发布样本；待复核条件计入待判；清单未有独立领域审定则验收失败 | 合同测试通过不会伪装成生产门槛通过 |
