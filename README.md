# 八字喜用判断引擎（bazi_core）

一个**确定性**（无随机、无集合序依赖）的八字喜用判断引擎。把传统命理中三套互相独立、经常"打架"的取用体系——**旺衰（扶抑）**、**子平格局**、**调候（《穷通宝鉴》）**——各自独立计算，再由一个**只读事实的仲裁层**按规则融合裁决，而不是简单地加权投票。

> 引擎版本：`season_v3 + direction_v7 + geju_v2 + tiaohou_v2`
> 仲裁政策：`policy_v29_counterfactual_maintenance_resolution`

---

## 1. 为什么这个项目存在

传统实战里，"调候、格局、旺衰"三套喜用经常给出互相矛盾的结论：调候说要水，格局说要火，旺衰说要木。主流做法要么是老师傅凭经验"拍脑袋"选一个，要么把三套喜忌五行并排平铺——后者看起来就像自相矛盾。

本项目的核心判断是：

> **三派不能"加权投票"，只能"分工 + 触发式主判 + 冲突记账"。**

因为三者回答的根本不是同一个问题：

| 维度 | 真正回答的问题 | 判据来源 | 决定的是 |
|---|---|---|---|
| **调候** | 这个环境能不能活、舒不舒服 | 《穷通宝鉴》日干 × 月令 | 生存质量、健康、心性底色 |
| **格局** | 这个人能到什么层次 | 《子平真诠》月令提纲 + 相神 | 社会成就的**上限** |
| **旺衰（扶抑）** | 这个层次他担不担得起 | 《滴天髓》旺者宜克、衰者宜扶 | 成就的**兑现度**、吉凶轻重 |

所以三者**不是同一把尺子**，不能用"数值谁大"来比，只能用"**序**"（谁主谁辅）来排。`bazi_core` 的全部设计都围绕这一点展开——这也是本项目最大的特色。

### 1.1 一棵树：用天时、地利、人和理解三套体系

如果把一个人比作一棵树，三套体系就在观察它生长所需的不同条件：

| 体系 | 树的比喻 | 人的比喻 | 要回答的问题 |
|---|---|---|---|
| **扶抑** | 根系、树干与枝叶之间的力量和承载关系 | 自身基础与能力配合，可借“人和”理解 | 自己能否承接环境带来的机会与消耗？ |
| **格局** | 土壤、水分、光照及周围植被形成的配合结构 | 所处的关系网络、组织和资源结构，犹如“地利” | 有利条件能否协同，冲突能否得到救应？ |
| **调候** | 生长所处的寒暖等季节条件 | 更大环境对生长的支持或限制，犹如“天时” | 当下是否存在必须优先处理的环境障碍？ |

从单点到系统看，自身力量像一个**点**；点所连接的关系与资源构成**线和面**；更大的环境背景像承载它们的**体**。同样的个人积累，在不同的时代、行业和组织中，可能获得完全不同的发挥空间。环境既可能放大个人力量，也可能限制它的兑现。

这是本项目帮助读者理解三者关系的思想模型。命理中的格局具体仍指月令、十神及其成破救应；调候具体仍按日干、月令等规则判断。时代、组织和“点线面体”是类比，不是从四柱直接测得的现实变量；扶抑也不能等同于努力程度。

### 1.2 一个指数式：自身基础如何被结构放大

还可以借一个数学表达，理解三者为什么需要一起考虑：

```text
成长示意值 Y = C × B^G

C：调候系数，表示环境允许其他条件发挥的程度
B：扶抑底数，表示有效的自身基础与承载能力
G：格局指数，表示结构带来的放大效应
```

- **调候像系数**：在这个示意模型中取 `C ≥ 0`。极端恶劣的气候可以理解为系数接近零，即使自身和结构有优势，也难以发挥。因此先让树活下来，其他优势才有意义。“不能为负”表达的是生长前提，实际用“接近零”比负数更贴近这个比喻。
- **扶抑像底数**：当 `B > 1` 时，更大的正指数带来增长；当 `0 < B < 1` 时，更大的正指数反而让结果缩小。例如 `1.1^10 ≈ 2.59`，而 `0.9^10 ≈ 0.35`。同样的放大结构，可能放大优势，也可能加剧承接不足与消耗。
- **格局像指数**：自身具备承接条件时，好的关系与资源结构能放大积累。结构提供的空间很重要，但它发挥什么效果，仍取决于环境前提与自身基础。

这里的 `B` 是“有效承载能力”的类比，**不是旺衰分数**，不意味着日主越旺越好；扶抑还要处理过旺、过弱及特殊结构。`C`、`B`、`G` 没有定义为可测量的人生成就参数，也不对应代码中的三个数值。这个式子用于解释依赖关系，**不参与引擎计算，不表示成就可以由八字定量预测**。

### 1.3 取舍逻辑：先识别当前最迫切的制约

天时、地利、人和没有适用于所有命盘的固定高低顺序。本项目希望先问：**这棵树眼下究竟卡在哪里？**

1. **气候有急病，先顾生长前提。** 天寒地冻、树将难以存活时，优先处理气候障碍；调候是否夺主，仍要核对原局条件、已有可用之字及替代方案，不能只因冬生就一律补火。
2. **自身承载有明显问题，重视扶抑需求。** 气候与环境尚可，但根系和树干不足以支撑消耗时，要考虑承接能力；同时检查扶助是否会破坏其他结构，不能把“身弱”直接推成全局无条件喜印比。
3. **调候、扶抑没有迫切需求时，以格局的结构配合为重。** 此时更值得关注资源能否流通、优势能否协同，以及结构中的病有没有适当救应。自身努力能取得怎样的成果，也受所处结构提供的空间影响。
4. **多项需求相撞时，说明选择与代价。** 增加日照可能有利生长，也可能加重缺水；同一个字可能满足调候，却损害格局。需要检查替代路线、成立条件和副作用，并记录为何此时让某一维度优先。证据不足时保留待判。

因此，融合的核心是：**分清各自解决的问题，按当前条件安排先后，让每一次取舍有据可查。**

这段描述解释的是设计思想，不额外定义一条“调候→扶抑→格局”的固定执行顺序。实际代码先处理特殊结构资格；普通方向融合按候选资格、支持与反对、季节次序等既定政策排序，中和区扶抑降权；严格仲裁另行核对需求与路线证据。当前可运行的启发式方向融合不等同于完整作用验证，跨维度生产评估与独立领域验证仍有待补齐。具体架构和门控规则见下文，不能用类比替代分支条件。

## 2. 算法总览：三派独立 → 仲裁融合

```
输入：四柱（干支）
│
├─ 排盘层 paipan.py
│   公历/农历/自然语言 → lunar_python 排盘 → 四柱 JSON
│   含真太阳时校正、经度校正、节气后天数、子时约定
│
├─ 三派并行独立计算（互不干预，各自保留原始结果）
│   ├─ 旺衰维度  wangshuai.py   → tag / 置信度 / 扶抑喜忌
│   ├─ 子平格局  geju.py        → 取格 / 相神忌神 / 病药 / 成破救应
│   └─ 调候维度  tiaohou.py     → 穷通宝鉴逐月取用序列 / 透藏 / 条件用
│
├─ 方向融合  direction_fusion.py（工程启发式）
│   季节取舍 + 多维度交集共识；冬夏调候优先、春秋格局优先、中和区扶抑降权
│
└─ 严格仲裁  arbitration.py（只读事实的政策层）
    外格门 → 调候门（条件门）→ 格局门 → 扶抑兜底
    + 路线生成 / 可采纳性 / 药效剂量 / 资源校验 / 冲突记账
```

关键点：**三派永远保留各自原始输出**，最终结论由方向融合（快、启发式）与严格仲裁（慢、政策化）两条路径之一给出，并显式记录每一条冲突的处置理由。

## 3. 三个独立维度的算法

### 3.1 旺衰维度（`wangshuai.py`）
- **月令系数 + 含日干生扶占比**：用月令气候权重修正旺衰，避免"只看日干被生扶几次"的粗糙计分。
- **生扶 / 克泄耗双指标 F、K**：结构化根记录（本气/中气/余气/微根），日支、月支被冲时权重打折。
- **置信度模型**：输出 `tag`（身旺 / 身弱 / 中和偏旺偏弱 / 从强 / 从弱 / 假从 / 虚旺）+ 置信度，而非武断二分。
- **特殊结构分支**：化气、从格（真从/假从）、虚旺（无根假旺）、中和区扶抑降权（`fuyi_policy`）。
- 旺衰兼容展示分 `effective_ws = 25 × 置信度` **仅供展示，明确不参与融合权重**。

### 3.2 子平格局（`geju.py`）
- **纯月令取格**：八格 + 外格（化气/从/专旺/两气成象）。取格规则：`唯一透出` → `多透按本气>中气>余气` → `都不透取本气标暗格`。
- **人元司令不参与取格**：司令只作 `siling_gan` 参考字段，不参与定格（与现行修订口径一致）。
- **格神 ≠ 喜神**（关键）：七杀格以七杀为格神，但七杀是凶神须逆用；吉凶标签只给**相神**与**药**。
- **病药体系**：成格无破 → 相神；成中有败 / 败中有救 → 药优先于相神；有病无救 → 真破格。
- 输出清浊、格局状态（`成格 / 成中有败 / 败中有救 / 真破格`）。

### 3.3 调候维度（`tiaohou.py`）
- 依据**《穷通宝鉴》十干逐月取用定本表**，按日干 × 月令给出**有序调候序列**（首用、次用、条件用、忌）。
- **分段格支持**：乙·酉（白露/秋分）、乙·午（夏至）、癸·辰（清明/谷雨）等原书分段，可显式 `--tiaohou-segment` 指定或自动推断。
- **透藏状态**：每个调候字标注 `透干 / 仅藏 / 原局无`，并结合合化判定（被合**未化**仍算在局；合而**化成功**视同原局无）。
- 条件用（`conditions`）仅在条件 active 时参与序列。

## 4. 核心特色：三派综合与选择（仲裁融合）

这是本项目与其它八字工具最本质的区别。融合**不靠加权**，靠一套**可判定的规则 + 冲突记账**。

### 4.1 一眼看懂：调候是"条件门"，不是"默认门"
《子平真诠》给的分界线是：**冬夏以调候为急，其余以格局为重**。所以仲裁层建模的是"**调候之病急不急**"，而不是"调候永远优先"。
- 冬 = 亥子丑、夏 = 巳午未，但**急度分 0/1/2 阶梯**（丑、未不剔除，反而是最极端的两个月）。
- 急度 = 季节基线（月支 + 节气段）× **局内五行修正**（否则退化成"冬生一律用火"）。
- 仅当气候极端（score=2）**且**调候主用不可用**且**无替代，才 `urgency=2` 夺主；否则调候只做药性修正或不夺主。

### 4.2 五道门裁决（触发式主判）
```
门0 外格门：化气/从/专旺/两气成象成格 → 顺势取用；旺衰与调候一并"挂起"（日主已质变）
门1 调候门：仅冬夏触发；首个"可用"调候字（首用不可用则取次用，30.7% 的盘靠这条翻盘）
门2 格局门：成格无破→相神；成中有败/败中有救→药；真破格→退门3
门3 扶抑门：格局破 → 扶抑优先；或与格局/调候叠用
（通关：目前作降级判据，未独立成门）
```
**分流 A（格未破）**：调候夺主时格局降为"层次判定"并记代价；**分流 B（格已破）**：调候兜底（标"待运"），调候也不可用则扶抑。

### 4.3 角色分离（根治"自相矛盾"的观感）
仲裁层给每个用神打 `role` 标签，同一字在不同层扮演不同角色，吉凶标签不通用：

`ROLE = {tiaohou, xiangshen, yao, fuyi, tongguan, external}`

- 格神（`ge_shen`）**只标"提纲/顺逆"，绝不标喜或忌**（七杀格的七杀是凶神）。
- 同一五行跨维度同向（如甲既是调候主用、又是相神、又是扶抑喜）→ 只占一个位置，`multi_dim=true`，**不许拆成三个位置**。
- 同五行合并（丙丁同火、壬癸同水），主字取"已透且有力"，另一字进 `alias`。

### 4.4 冲突分类学（四类，各有定法）
融合层最重要的产出不是"一个答案"，而是"**冲突清单 + 每条的处置理由**"：

| 类型 | 长相 | 真冲突？ | 处置 |
|---|---|---|---|
| **A 语义冲突** | 同字一边叫格神、一边叫忌神 | 否 | 分角色输出，禁止把格神标成喜/忌 |
| **B 层次冲突** | 格局成格但身弱"担不住" | 否 | 双结论：`层次=成格（高）` + `兑现=身弱不担`，**不合并成"不贵"** |
| **C 真冲突** | 同五行调候判喜、扶抑判忌 | 是 | C1 保命档 / C2 保格档 / C3 无力档 三档处置 |
| **D 结构冲突** | 调候首选字正好破格 | 是（最危险） | **格为纲**：首选标"破格需权衡"，改取不破格的次用；若次用也不可用，明写"以层次换生存" |

### 4.5 输出契约（可审计、可回归）
```
final_xiyong.positions  : 固定 ≤3 个位置（主用/辅用/条件用）
verdict                : { layer, delivery, climate } 三层定性
conflicts              : 每条冲突的 type / between / element / resolution
priority_reason        : 一句话说明为什么这层夺主（非空，可对应分支名）
avoid                  : 只放确定破坏主用的字（护栏防"同字既用又忌"）
```
**不变量（部分）**：位置长度 ∈ {1,2,3}；三个位置不得出现两个同五行；`mode=external` 时任何位置不得含调候；`marks` 含"权用"必有一条同 element 的冲突记录；同一盘两次调用结果完全一致。

## 5. 快速开始

### 依赖
```bash
pip install -r requirements.txt   # 仅 lunar_python（纯历法，无绘图依赖）
```

### 命令行用法（`cli.py`）
```bash
# 自然语言生辰（公历/农历自动识别），真太阳时 + 经度校正
python cli.py --birth "1990年五月初五辰时" --sex male --lon 117.2 --truesun

# 显式公历
python cli.py --y 1990 --m 5 --d 5 --h 8 --minute 0 --sex male --lon 117.2 --truesun

# 直接给四柱（跳过排盘）
python cli.py --chart "庚午 甲申 庚子 壬午" --solar-term-day 5 --trace

# 纯 JSON 输出（便于接入其它系统）
python cli.py --birth "..." --json
```

常用参数：
- `--truesun` + `--lon`：真太阳时 + 夏令时回拨 + 经度校正
- `--lunar` / `--leap`：农历输入 / 闰月
- `--tiaohou-segment`：调候分段（段A/段B/上半月/下半月/清明后/谷雨后）
- `--trace`：打印格局判定链路日志
- `--no-special-ge`：关闭外格前置筛查
- `--sect {1,2}`：晚子时日柱约定（默认 2）

### 作为库调用
```python
from bazi_core.engine import analyze
from bazi_core.paipan import analyze_birth

# 给定四柱
result = analyze({"year": {"gan":"庚","zhi":"午"}, ...})

# 给定生辰
result = analyze_birth(birth="1990年五月初五辰时", sex="male", lon=117.2, truesun=True)
```

## 8. 设计原则（贯穿全代码）

1. **三派各自保留原始输出**，融合层只读不改；结论可追溯到任一维度。
2. **融合只用"序"，禁用跨维度数值比较**——三套力量尺（F/K、格局 1/1/0.5、调候无数值）本不可横向比大小。
3. **确定性**：无随机、无集合序依赖；同一盘两次调用结果完全一致（硬性不变量）。
4. **角色分离根治观感矛盾**：格神不标喜忌，同字跨层只标角色不相加。
5. **冲突显式记账**：不是消灭冲突，而是把每条冲突的类型、涉及维度、处置理由写清楚。
6. **未审定不冒充生产结论**：证据不足的维度与药效剂量只标 pending / 待核，不强行给确定答案。

## 9. 已知边界（V1 明确不做）

- **盲派体用层**：只做"兑现度"校验（宾主/制尽），不参与喜用裁决。
- **支合绊的藏根扣减**：`root_w` 只扣冲，不扣六合/三合绊。
- **岁运吉凶**：本引擎只出原局喜用；岁运须另设基准（已用"待运"兜住）。
- **神煞 / 奇格 / 拱夹**：只入 `flags`，只影响应期与象，不参与主判。
- **通关**：目前只作降级判据，未独立成门。
